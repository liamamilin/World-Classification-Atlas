# Codex 交接说明：World Classification Atlas

## 当前背景

用户决定暂不研究或预设“九类需求”，也暂不做需求理论。World Classification Atlas 优先研究现实世界现成的分类目录，逐领域建立自有目录。现实实体、商品、组织和服务提供者的连接是**之后的独立研究方向**，当前不开发。

## 最终成品

用户能按领域查看所有已登记的标准来源；查看其原始各层级目录、代码、定义和不同版本；查看我们依据多源标准整理的自有目录（领域 → 目录 → 任意层级 → 叶子），并追溯每个节点如何对应原始分类。目录对象不同就保留为不同树，不强迫形成一棵世界树。

## 请 Codex 按以下顺序推进

### 工作 1：把来源候选转为核验后的分类注册表
- 检查 15 领域范围是否有显著缺失；从 UNSD Family、Eurostat RAMON 和各专业官方门户扩展，去重。
- 逐条核实官方发布者、名称、分类对象、明确版本、原始层级、官方地址、可下载格式、对照表和许可。
- 保留候选/核实/不可访问/需许可等状态与证据，不臆造数据。
- 构建**可持续增加来源**的结构化注册表和浏览视图；先覆盖信息源的完整性与正确性。

### 工作 2：将允许下载的源目录资料拉取到本地
- 设计简单可复现的下载任务和资源清单；优先结构/代码/定义/手册/官方对应表。
- 原文件不变，按 source_id/edition 组织；计算哈希并写 manifest。
- 验证原文件可解析、层级数量、父子关系，输出失败、限制和统计；禁止将未下载标作已完成。
- 对非公开许可或仅能在线查看的标准记录元数据与链接，不强行复制入公开仓库。

### 工作 3：一个领域一个领域地处理
- 每个领域先识别不同分类对象，**不能只因处于同领域就合并**。
- 解析源节点后对照概念、定义、范围、父子路径；官方映射优先。
- 给出统一目录候选与每条映射的证据，自动化用于候选提议；重要合并与结构变更审阅。
- 保存自有 scheme 和 node 稳定 ID，保留来源可逆追踪、冲突、待映射项和检查报告。
- 输出可浏览的多层级自有目录。

### 工作 4：跨领域 Atlas 应用
- 领域与目录选择、源目录/自有目录的树状导航、搜索、定义、原码/版本、来源追溯、映射比较、未处理统计。
- 本地运行/静态发布优先；不为现阶段增加组织/商品实例、账户/支付或昂贵基础设施。

## 审查标准

按实际源文件和可追溯证据报告节点统计与覆盖，不能以生成的“世界目录”代替采集。记录对照标准的语义差异，禁止同名直接合并。允许空白/未核实/未映射。保证不同源版本不会混写。关键在真实能力，不在复杂多 Agent 编排和繁琐门禁。

## 先前讨论的核心共识

- 主体是 World Classification Atlas，不再仅是 Demand Atlas。
- 先完成目录自身的体系，**绝不提前做分类与现实实体关联**。
- 15 领域是导航，不是终极理论。
- 最终有属于 Atlas 的统一目录，但**统一不等于强制单树**。
- 不反复提出第一/第二版本的目标变化，按完整终点的工作依赖逐步实现。

## 立即开始的动作

先检查仓库实际文件与权限，审阅这套资料的遗漏或矛盾，再把“分类来源注册表”的资料验证能力实现出来。提交真实可运行的工具和数据、给出可复现命令、来源核验状态及下一步受阻点。不要在尚未抓取来源时声称已完成目录合并。
