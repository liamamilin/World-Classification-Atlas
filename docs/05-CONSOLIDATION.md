# 分类目录整理与融合原则

## 先判定分类对象，再决定合并

**同一领域不等于同一分类对象。**

例子：
- ISIC / NAICS / NACE / GB/T 4754 主要分类经济活动，可进行仔细的跨体系比较。
- CPC（Central Product Classification）/ HS / UNSPSC 有商品交叉部分，但产品/服务覆盖与分类目的不全同；允许部分映射，不强制完全等同。
- ICD-11 分类疾病与健康相关状况；ICF 分类功能与参与；ATC 分类药物；不得合成单一“医学目录”。
- ISCED 教育层次与 ISCED-F 教育领域分别组织。

同一术语并不等于同一概念；不同术语也不意味着不等价。

## 源目录永远保真

保存每个 source_id + edition + source_code 的身份、原始标签、定义、全部父级关系和引用。禁止修改官方数据来迁就自有目录。可能存在 polyhierarchy / facets / cross-reference，不能强制解析为唯一树。

## 自有目录可以有多套

每个 Atlas Scheme 要有清楚的“分类对象”和纳入/排除范围、层级原则、来源版本集合。目录的深度不限：一级/二级/三级/…/叶子，由实际分类内容决定。自有节点使用稳定自有 ID，原始标准代码只作来源对应。

## 合并决策

1. **等价（exact）**：定义、适用范围和分类对象实质一致；可作为同一 Atlas 概念的多个来源依据。
2. **接近（close）**：范围基本相似但不完全重合；仍保持差异，不自动完全合并。
3. **上位/下位（broader/narrower）**：一方范围明确包含另一方；记录方向和具体理由。
4. **相关（related）**：对象或语义相近，但不存在可证明等价或包含；建立关联。
5. **无对应 / 待审**：保留未映射节点；不为追求覆盖率创造虚假关系。

优先源标准官方 crosswalk/correspondence。LLM/向量只用于候选提议，不得独立确证等价。人工审核不必审查所有简单匹配，但应覆盖含义变化、合并、拆分、争议和高影响判断。

## 融合策略

选择具备范围与定义质量的源作为局部骨架；补充其他源中覆盖的缺口；允许产生新上位节点帮助导航，但必须标注为 Atlas 自创，不能冒称官方；保持可回溯到多个源节点。多个来源有冲突时保留冲突与解释，避免“统一”沦为强行抹平差异。

自有目录的单一显示路径不应成为概念唯一语义：允许节点与多个目录/路径建立关联；用户界面可展示一个主路径以方便浏览。

## 验收

可从任意自有节点追溯来源；能从源节点找回被映射到的自有节点；重复/冲突/遗漏均可统计；分类层级没有循环或误归属；新增来源和更新版本不会造成不可解释的大规模变更。

借鉴 W3C SKOS 的概念组织和映射语义，但不要求一定使用 RDF 或图数据库。
