# 原始资料采集与本地化规范

## 原则

**来源登记不是资料下载**。source-candidates.csv 是待核验索引，不代表本地已缓存数据。

每套标准按“来源 scheme + 明确版本 + 资源文件”建档。优先官方分发入口；必要时允许可信镜像，但必须标注次级来源，不得伪称官方原件。

## 需要寻找的资料

分类代码与层级结构、完整定义和注释、范围边界与排除条款、官方释义手册、版本与修订说明、不同版本的 concordance/correspondence、跨标准官方映射、许可与再分发条件。

按资源分别保存 URL、文件名、原始字节 SHA-256、下载日期、发布日期或版本、MIME/格式、原始语言、许可状态、下载结果及错误说明。

## 推荐本地布局（建议，可在实现时调整）

```text
data/
  source-candidates.csv       # 初始来源发现入口
  registry/                    # 核验后的标准和版本元数据
  raw/<source_id>/<edition>/   # 原始不可变资料
  normalized/<source_id>/<edition>/ # 解析后的源节点
  atlas/                       # 自有目录与映射
  reports/                     # QA 与覆盖情况
```

不得在同一位置覆盖已有版本快照；新发布版形成新快照。原始来源可保留为下载缓存/本地存储，不应不加筛选推送到公开仓库。

## 许可和风险

开放访问 ≠ 允许重发布。分别确认：访问许可、下载许可、本地处理许可、公开再分发许可、衍生作品和署名条件。对 SNOMED CT、DDC、eCl@ss、UNSPSC、Getty 等需要逐一核验，不推定全部开放。

有授权限制时：先登记元数据、官方链接、许可证与缺口；不要绕过登录或限制；仅在许可范围内获取和展示数据。对法律、医学和专利等复杂分类保留官方定义，避免生成内容伪装为官方文本。

## 可复现与 QA

- 检查数据文件可解析、字符编码与压缩包完整。
- 保留原始编码与代码格式，尤其保留前导零和点号。
- 父子层级、重复代码、孤儿节点、循环、自引用、废止节点、别名、非树关系均生成检测报告。
- 对照发布方的节点数量/层级统计（若可得）；若无法核对则标未知。
- 源数据解析失败不能悄悄删除条目；保存失败样本。
- 定义与翻译来自何处必须可区分（官方/人工/模型）。
- API/网页采集应尊重服务条款、robots、限速和合理请求量。
