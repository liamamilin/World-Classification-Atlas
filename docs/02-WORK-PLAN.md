# 工作方案：盘点 → 本地化 → 分领域融合 → Atlas

以下各项按依赖关系执行，所有工作服务同一个最终成品，不以“第一版/第二版”重新定义目标。

## A. 盘点世界上现存的分类目录

建立**源目录注册表**：标准标识、正式名称、别名/缩写、管理机构、官网、分类对象、所属领域（可多个）、层级结构、最新可确认版本、许可证、下载入口、是否可机器读取、官方对照表、更新政策、验证日期、状态与备注。

从 UNSD International Family of Classifications、Eurostat RAMON、官方标准制定机构和各领域权威入口扩展，按 15 个领域盘点。**注册表中的候选不意味着已核实**。

验收：每个候选都能定位到可查的机构或官方入口；缺失信息标待核实；能识别同一分类的不同名称、不同版本和不同分类对象。

## B. 将分类的相关资料保存到本地

对于许可允许下载/存储的标准，保存**原始版本不可变快照**：分类结构、代码表、定义/说明、手册、交叉映射、许可说明、采集清单、文件哈希 SHA-256、获取时间与源 URL。

对网页/API/压缩文件/CSV/Excel/PDF 采取不同适配器；记录失败，不将无法访问当成分类不存在。对商业或限制再分发材料先保存元数据与链接，获得授权后再决定是否复制。

验收：任意已下载文件可追溯其原始来源；重复运行可检测内容变化；原始数据不会被规范化处理覆盖。

## C. 逐领域进行研究与整理

每领域：
1. 明确其中有哪些**分类对象**，避免将同领域下不同对象混合；
2. 选择要比较的源标准和具体版本，统计节点、层级、定义质量；
3. 解析为统一的**源节点表示**，保留原有代码、路径、父级、定义与历史；
4. 候选映射：等价/近似/较宽/较窄/相关/无对应；优先使用官方对应表；
5. 按共同对象形成自有 Atlas Scheme；决定沿用骨架、增补、拆分、合并或保留并列；
6. 审核冲突和来源证据，记录变更理由、待处理问题；
7. 产出自有目录的可浏览结构及与源目录的映射报告。

每领域不是必须整合成一棵树。自有目录可多树、多层级；同一个概念可与不同源多对多映射。不要把所有源树重新排序后称为“统一”。

验收：抽样自有节点能解释为什么存在、属于哪里、来源是什么；源节点不会无声丢失；待映射项可统计。

## D. 汇聚整个 Atlas

完整体验：
- 按领域发现原始分类和自有目录；
- 原始目录结构浏览（任意深度）；
- 自有目录浏览与叶子检索；
- 双向查看源代码与 Atlas 节点的映射；
- 筛选源标准/版本、搜索代码/名称/别名/定义；
- 看到每一目录的覆盖率、未映射项、冲突与来源变更；
- 导出独立可复现的结构化数据。

先定义领域/目录/节点/映射的逻辑契约，再在技术上选择存储和浏览方案。建议本地批处理 + SQLite 索引 + 可静态发布的浏览前端；若需求要求在线更新才增加服务端。**技术候选不是不可替换的项目原则**。

## 执行顺序和交接要求

先完成 A 的来源登记质量，再启动 B 的真实下载；不等所有来源全部下载完成才允许分领域处理，而是保证每个进入处理的源已有合法、本地可验证的快照。领域处理结果可以持续加入全局 Atlas。

不提前强制按某一个领域排序；优先选**数据完整、开源可获取、分类对象清楚、有可验证官方对应关系**的领域做融合工艺检验，再扩展。不可仅因容易处理就永久忽略困难领域。

每次执行报告应包含：完成内容、事实证据、数据规模、失败与受限来源、未决决策、仓库提交。禁止以模型猜测的节点、代码和统计值充数。

## 目前尚需实测的工程风险

源格式与版本漂移；大量节点/关系的检索性能；授权下载和二次发布限制；不同标准的分类范围与粒度冲突；非树状源结构；多语映射质量。通过真实数据小规模完整试验验证工艺，但**不改变最终目标**。
